## 1. Design

### 1.1 State additions (`resolve.state`)

| Where | Field | Rules | Notes |
|---|---|---|---|

| new `TurnState` (mutable slots dataclass, `state/turn.py`) | `number`, `active_player`, `phase: Phase`, `step: Step \| None` (None in main phases, 505.2), `priority: PlayerId \| None`, `passed: list[PlayerId]` (players who passed in succession since the last action, 117.4), `lands_played: int` (active player, 305.2a) | 500.1, 117.3, 305.2 | Priority holder lives in state, not in a task, so views and the scenario builder can see/set it (design §14) |

`invariant_violations` grows checks for each: turn fields consistent, priority holder in the game,
status only on permanents, players who left own no objects, mana only in pools of players in game.

### 1.2 Characteristics and type lines (minimal, no layers yet)

- `CardFace` gains parsed type-line fields at load (`resolve.data.cards.parse_type_line`):
  `supertypes` (205.4a), `card_types` (205.2a, enums), `subtypes` (strings). Unknown words are a
  load error (refuse, never guess).
- New `resolve.effects.characteristics.characteristics(state, obj) -> Characteristics` (immutable):
  name, types, subtypes, power/toughness as ints (`"*"` etc. → `NotImplementedRule("208.2: ...")`
  when read), abilities. It starts from the card face and applies **no** continuous effects (none
  can exist until M5). This is the single entry point M5 fills with layers; no cache yet.
- Abilities: `CardDefinition` gains `abilities: tuple[Ability, ...] = ()` (empty for every M1 card).
  `characteristics` adds the **intrinsic** 305.6 mana ability for each basic land type on a land.

### 1.3 Primitives (first entries in `docs/primitives.md`)

- `ActivatedManaAbility(cost, effect)` (`cards/primitives/abilities.py`), 605.1a, 605.3.
- `TapSelfCost` ({T}) (`cards/primitives/costs.py`): payable iff the permanent is untapped (118.3,

### 1.4 Events (`resolve.events`)

All through `ApplyEvents`; each cites its rules.

- Turn: `TurnBegan`, `StepBegan(phase, step)` (500.6 — this is what M4's "at the beginning of"
  triggers will match), `PriorityPassed(player, mana_in_pool)` (117.3d, 106.4b announcement).
- Drawing / mulligans: `CardDrawn(player, from_obj, to_obj)`, `DrewFromEmptyLibrary(player)`
  (121.4), `MulliganDeclared(player, take)` (103.5, public per 101.4b),
  `HandShuffledIntoLibrary(player)` + existing `LibraryShuffled`, `CardsPutOnBottom(player, objs)`.
- Lands / mana: `LandPlayed(player, from_obj, to_obj)` (305.1, 116.2a), `PermanentTapped`,
  `PermanentsUntapped` (502.3, 701.26), `ManaAdded` (106.4), `ManaPoolEmptied` (500.5, 703.4q).
- Cleanup / SBA: `CardDiscarded` (701.9a, 514.1), `DamageRemoved` (514.2), `PermanentDestroyed`
  (701.8a, 704.5g), `PutIntoGraveyard` (704.5f — not "destroy", 701.8b), `PlayerLost(player)`
  (704.5a/b, 104.3a), `PlayerLeftGame(player)` (104.5, 800.4a), existing `GameEnded`.

**Engine-core change needed (see §3):** `Event.apply` returns the event *as applied* (default
`self`) so zone changes can log the new `ObjectId`; `LogEntry` gains an optional redacted `public`
form shown to players outside `visible_to` (draws, bottoming, shuffling hand back).

### 1.5 Decision kinds and options (`resolve.decisions`)

- Kinds: `MULLIGAN` (exists), `PRIORITY_ACTION` (exists), new `PUT_ON_BOTTOM` (103.5; reused by
  Gishath/discover later), `ORDER_CARDS` (order of cards put on the bottom), `DISCARD` (514.1).
- New typed options (the `Option` union): `NamedOption(name)` (keep/mulligan, later yes/no),
  `PassOption()`, `PlayLandOption(object)`, `ActivateAbilityOption(object, ability_index)`,
  `CastSpellOption(object)`.
- Spaces reused: `ChooseOne` (mulligan, priority), `ChooseSubset` exactly N (bottom, discard),
  `ChooseOrder` (bottom order; answer lists the cards top to bottom of that group).
- Policy (to record in decisions.md): a decision with exactly one legal answer is not asked
  (forced keep at hand size 0, bottoming the whole hand), **except priority**, which is always
  asked (auto-pass is agent-side, design §6).

### 1.6 Tasks

- `OpeningHands` (103.5) replaces the gap. Fields: `mulligans: dict[PlayerId, int]`,
  `kept: list[PlayerId]`, `declarations: dict[PlayerId, bool]`, a stage marker.
  1. `DrawCards(player, n)` for each player in turn order from the starting player (121.2c,
     101.4e).
  2. Ask `MULLIGAN` of each undecided player in turn order from the starting player; log
     `MulliganDeclared` publicly.
  3. All who mulligan, together: one `ApplyEvents` moving each hand into its library and
     shuffling (turn order), then their draws (121.2c), then `PUT_ON_BOTTOM` (+`ORDER_CARDS` when
     ≥2) asked in APNAP order, then one `ApplyEvents` putting all chosen cards on the bottom
     (101.4: choose in order, act simultaneously). The owner keeps knowledge of the bottomed
     cards (`known_to`), cleared by the next shuffle.
  4. Repeat until nobody mulligans. Counted mulligans = taken − 1 in a multiplayer game (103.5c,
     100.1b: "begins with more than two players"); bottom count = counted mulligans; a player
     whose hand would be 0 isn't asked again.
  5. 103.6 (opening-hand actions): no definition can have one; comment only. Push `TakeTurn`.
- `DrawCards(player, count, rules)`: one `ApplyEvents` per draw (121.2, so M6 replacements apply
  per draw, 121.6b); an empty library logs `DrewFromEmptyLibrary`.
- `TakeTurn(player)`: `TurnBegan`, then each step: `BeginStep` (`StepBegan`, 500.4 expirations —
  none exist) → turn-based actions → `PriorityRound` if the step has priority → `EndStep`
  (500.5 expirations, then `ManaPoolEmptied` for every non-empty pool, 703.4q). Skips the starting
  player's turn-1 draw step in a two-player game (103.8a/c, 500.11). Then pushes the next
  `TakeTurn` for the next player in turn order still in the game (800.4k).
  - Untap: 502.1 phasing and 502.2 day/night are vacuous (nothing can have them; comment);
    502.3 untaps all of the active player's permanents in one event, no decision (no effect can
    stop untapping yet).
  - Draw: 504.1.
  - Combat: 507.1 — no defending-player choice (two players, or 802.2 in multiplayer; see §3).
    508.1: if the active player controls no creature, the declaration is empty and 508.8 skips
    declare blockers and combat damage; otherwise `NotImplementedRule("508.1: declaring
    attackers (roadmap M3)")`.
  - Cleanup: 514.1 `DISCARD` exactly (hand − max hand size), max hand size 7 (402.2; not the
    starting hand size); 514.2 `DamageRemoved` on all permanents; 514.3a: if the SBA check
    performs anything (or triggers wait), the active player gets priority and another cleanup
    step follows.
- `PriorityRound`: loop of `CheckStateBasedActions` (repeat until none, 704.3) →
  `PutTriggersOnStack` (no-op until M4, but in the 117.5 loop) → ask the holder
  `PRIORITY_ACTION`. Pass → `PriorityPassed`; if every player still in the game has passed in
  succession: empty stack → step ends; non-empty stack → `NotImplementedRule("608.1: ...")`.
  Any action → same player gets priority again and `passed` resets (117.3c, 116.3, 117.4).
- Priority options (enumerated, deterministic order): Pass; `PlayLand` for each land card in hand
  if active player, main phase, empty stack, lands_played < 1 (305.1–305.3, 116.2a);
  `ActivateAbility` for each mana ability whose cost is payable (605.3a, 118.3);
  `CastSpell` for each nonland card in hand the timing rules allow (117.1a, 302.1, 304.1,
  307.1; 305.9). **Choosing `CastSpell` raises `NotImplementedRule("601.2: casting spells
  (roadmap M2)")`** — offering it keeps the legal-action set true for AIs; hiding it would be a
  silent simplification.
- Mana ability activation: pay `TapSelfCost` (`PermanentTapped`), resolve immediately
  (`ManaAdded`), no stack object (605.3b).
- `CheckStateBasedActions`: computes all of 704.5a, 704.5b, 704.5f, 704.5g at once into one
  `ApplyEvents` (704.3 "single event"), clears the empty-draw flags, reports whether anything was
  performed (for 514.3a), then `LeaveGame` for each player who lost (104.5), APNAP order.
- `LeaveGame(player)`: `PlayerLeftGame` (800.4a: objects the player owns leave the game; guards
  raise `NotImplementedRule("800.4a: ...")` if the player controls objects others own or there
  are stack objects — impossible in M1), passes priority on if the leaver held it, then the end
  check: one player left → `GameEnded(winners=(p,))` (104.2a); none → draw (104.4a).

### 1.7 Concession (`resolve.engine.concede`)

`concede(state, player)`: rejects (nothing changed) if the game is over or the player already
left. Otherwise: logs a public `ConcessionRecord`, withdraws the pending request (its id becomes
stale), pushes `PlayerLost(104.3a)` + `LeaveGame` above the paused task, and runs the loop. The
paused task's `run()` is then called again and must re-ask (with a new request id) or skip a
player who left (800.4h: a rule's choice moves to the next player in turn order). Contract for
all asking tasks: `run()` is safe to call again after returning `NeedDecision` (StartGame must
stop re-drawing its chooser from the RNG). Turn without an active player continues (800.4j).

### 1.8 Views, cards, tools

- `PlayerView`: turn number/phase/step/active player/priority holder, each player's mana pool,
  life, in-game status; `ObjectView` gains `tapped`, `damage`. Log entries shown in their public
  form to non-viewers.
- Cards (`src/resolve/cards/definitions/`): `basic_lands.py` — Plains, Island, Swamp, Mountain,
  Forest (all five, since 305.6 is one rule; target decks use Forest/Plains/Mountain);
  `vanilla_creatures.py` — Grizzly Bears, Savannah Lions, Hill Giant (to be confirmed vanilla
  against the snapshot when implemented; none of the target decks' creatures are vanilla).
  Fixtures for each added to `tests/scryfall_fixtures.py`.
- `tests/scenario.py` (from the M0 session) is extended with turn, step, active player, priority
  holder, lands played, tapped, damage and mana pools. `play_cli.py` renders the new view fields.
  The fuzz harness's "M0 ends at 103.5" rule becomes "ends at game over, or at a
  `NotImplementedRule` (counted and reported)", with land-only decks expected to always finish.

## 3. What seems wrong or underspecified (needs your call where marked ★)

1. ★ **Leaving the game is M7 in the roadmap, but M1 needs it.** Concession (104.3a) and SBA
   losses make the player leave (104.5); in 3+ player games play continues (800.4).
   Recommendation: M1 implements 800.4a/h/j/k for what can exist in M1 (cards only; no stack
   objects, tokens or control changes) with `NotImplementedRule("800.4a: ...")` guards for the
   rest; M7 keeps the full consequences. Alternative: gap every multiplayer loss until M7.
2. ★ **Concession interrupts a paused task.** Design §3/§5 don't say what happens to the pending
   request. Proposal in §1.7: withdraw it, run the leave, call the paused task's `run()` again
   (re-ask with a new id). Requires the re-entrancy contract and a fix to `StartGame.run`, which
   currently re-draws the chooser from the RNG.
3. ★ **Replays (design §12) are "seed + answers"; concessions aren't answers.** Change to "seed +
   ordered inputs (answers and concessions)", with a `ConcessionRecord` in the log.
4. **Log redaction (design §9 says "designed in M1").** `LogEntry` visibility is all-or-nothing,
   and zone-change events don't record the new `ObjectId` (`CommanderPutIntoCommandZone` logs
   only the old one). Proposal: `Event.apply` returns the applied event; `LogEntry.public` holds
   the redacted form for other players.
5. ★ **Commander mulligans.** design.md §10 lists "mulligan rules per the config" under Commander,
   contradicting "deliberately not parameters: a mulligan rule", and roadmap M7 has "Commander
   mulligan rules". The pinned CR has none for Commander (903 says nothing; 103.5c covers
   multiplayer; 903.12g is Brawl only). Proposal: delete both mentions.
6. ★ **Multiplayer attack option.** 806.2b requires one of attack left/right/multiple; 903.2
   defaults Commander to attack multiple players; `GameConfig` says nothing for non-Commander
   multiplayer. Proposal: every multiplayer game uses Free-for-All with attack multiple players
   (802.2: no 507.1 choice), as a deliberate non-parameter.
7. ★ **Offering unimplemented actions.** Hiding "cast a spell" in M1 would be a silent
   simplification; proposal is to offer it and raise `NotImplementedRule("601.2")` when chosen
   (same pattern in PR 2 for land plays/mana abilities until PR 3). Random-agent games with
   nonland cards will often end at that gap until M2.
8. **103.5 "until their opening hand would be zero cards".** Read as: the mulligan that leaves
   zero cards is allowed, then no more. Recorded in decisions.md and test 11's docstring.
9. **Option types.** Only `PlayerOption`/`ObjectOption` exist; priority and mulligans need typed
   action and named options (§1.5). Design §6 already anticipates "typed options".
10. **Characteristics.** Design §8 says "cached, invalidated on any change". Proposal: no cache
    until the benchmark asks for one (invalidation bugs are correctness bugs). `CardFace` has
    no parsed types; parse at load.
11. **Turn state is listed in design §4 only as a bullet.** §1.1 makes it concrete (priority holder
    and pass tracking in state). Mana pools aren't in design §4 at all.
12. **Existing tests that assert the 103.5 gap** (`test_103_5_opening_hands_are_not_implemented_
    yet...`, `choose_starting_player`, `test_after_a_rules_gap_...`, the 103.3 permutation tests,
    `test_rule_citations` using the gap) must change: they test a gap M1 closes. They'll be
    replaced by tests of the new behavior (and a test-only task for "after a gap"), never
    loosened — flagged so it's not read as weakening.
13. **Coordination with the M0 session**: the fuzz harness's terminal condition and the scenario
    builder's fields both change in M1 (PR 1 and PR 2).
14. Minor: `view_for` copies the whole log on every call (quadratic over a long game); fine for
    now, worth a cursor later. `concede` errors: reuse `InvalidAnswer` ("rejected, nothing
    changed") rather than a new exception.
